# ControllerFlow 执行计划

## 已确认的产品约束

- Profile 由用户创建，用户自行选择目标软件并配置按键映射。
- 主链路固定为 `Input -> Router -> 当前 App 对应的 Profile -> Output`。
- Router 根据 Windows 当前前台应用选择 Profile，并支持默认 Profile 兜底。
- 语音使用第一种方案：按住映射键时调用用户指定的本地语音转文字工具或快捷键，松开时结束。
- 映射执行后支持手柄震动反馈，反馈参数可随 Binding 配置。

## 阶段

1. **工程骨架与核心边界**（本轮）
   - 建立 WPF App、Core、Windows Infrastructure、Core Tests 四个项目。
   - 定义输入事件、App 身份、Profile、Binding、Output Action、震动反馈模型。
   - 定义输入源、前台 App、Profile 仓库、输出执行、震动端口。
   - 实现不依赖 Windows API 的 Profile 选择与按键路由。

2. **手柄输入层**
   - 使用 Windows.Gaming.Input 读取手柄并支持热插拔。
   - 将不同型号手柄统一转换为按下、释放、长按事件。
   - 处理摇杆死区、按键抖动与重复触发。

3. **前台应用与 Router**
   - 通过 Win32 获取前台窗口、进程名、路径和窗口标题。
   - 支持进程名、完整路径、窗口标题正则匹配。
   - 在前台应用变化时切换 Profile，并显示当前命中结果。

4. **用户映射与输出层**
   - 完成 Profile/Binding 的 JSON 读写、校验、导入与导出。
   - 实现键盘组合键、鼠标、媒体键、启动程序等输出。
   - 支持按下/释放配对，避免组合键卡住。

5. **语音方案**
   - 用户配置本地语音转文字工具或其快捷键。
   - 手柄按住时启动/按下，松开时停止/释放。

6. **震动反馈**
   - 支持成功、无匹配、执行失败三类反馈。
   - 支持每条 Binding 覆盖强度和时长。

7. **桌面体验**
   - 完成 Profile 编辑、按键捕获、目标 App 拾取、实时测试。
   - 增加托盘、开机自启、配置引导、自检与日志。

8. **交付**
   - 补齐单元测试和 Windows 集成测试。
   - 发布 self-contained x64 安装包和使用说明。
